# Nginx Tools

Две утилиты для работы с Nginx. `update-symlinks.sh` управляет включёнными конфигурациями сайтов, а `nginx_log_analyzer.py` строит отчёты по access- и error-логам.

## Управление конфигурациями сайтов

`update-symlinks.sh` работает с установками, где конфигурации хранятся в `/etc/nginx/sites-available`, а Nginx подключает их через `/etc/nginx/sites-enabled/*`. Используйте Bash на Linux с GNU coreutils, `flock` из util-linux и командой `nginx` в `PATH`. Для применения изменений нужны права root. Предварительный просмотр требует доступа на чтение к каталогам.

~~~bash
# Посмотреть, что изменится для двух сайтов
bash update-symlinks.sh --dry-run example.conf api.conf

# Включить указанные сайты
sudo bash update-symlinks.sh example.conf api.conf

# Посмотреть план массовой синхронизации
bash update-symlinks.sh --dry-run --all

# Применить план массовой синхронизации
sudo bash update-symlinks.sh --all
~~~

- Передавайте имена файлов из `sites-available`. В этом режиме скрипт меняет ссылки только для выбранных сайтов.
- `--all` включает все подходящие конфигурации из `sites-available`. В том числе те, которые ранее хранились там выключенными. В этом режиме скрипт также удаляет устаревшие видимые ссылки, ведущие в `sites-available`.
- Скрипт пропускает скрытые файлы, каталоги, битые ссылки и распространённые служебные файлы, включая `*.bak`, `*.tmp`, `*.dpkg-*` и `README*`. Обычные файлы и ссылки на другие каталоги сохраняются. Если такая запись занимает имя выбранного сайта, операция завершается до внесения изменений.
- `--dry-run` выводит план. При применении скрипт проверяет конфигурацию с помощью `nginx -t` и запрашивает reload запущенного Nginx. Проверка и reload выполняются и тогда, когда ссылки уже совпадают с планом. Это позволяет применить изменения в содержимом конфигов.
- Если изменение ссылки, `nginx -t` или команда reload завершается ошибкой, скрипт восстанавливает прежние ссылки. Если восстановление не удалось, он указывает каталог с оставшимися резервными копиями. Запуски скрипта блокируют друг друга на время применения изменений.

Для reload скрипт использует активную службу `nginx` через `systemctl`. Если такой службы нет, он ищет запущенный процесс через `pgrep` из procps и использует `nginx -s reload`. При остановленном Nginx выполняется только проверка конфигурации.

## Анализ логов

`nginx_log_analyzer.py` использует стандартную библиотеку Python 3. Для запуска нужны права на чтение логов. Без пути открывается меню с файлами из `/var/log/nginx`. Для другого каталога меню передайте `--log-dir`.

~~~bash
python3 nginx_log_analyzer.py
python3 nginx_log_analyzer.py /var/log/nginx/access.log
python3 nginx_log_analyzer.py /var/log/nginx/error.log.2.gz --type error
python3 nginx_log_analyzer.py /var/log/nginx/access-json.log --type json
python3 nginx_log_analyzer.py /var/log/nginx/access.log --tail
~~~

Поддерживаются access-логи в стандартном формате `combined`, обычные error-логи Nginx и JSON Lines. В режиме `auto` скрипт смотрит на первые строки и использует имя файла, если по содержимому формат определить не удалось. Для явного выбора используйте `--type access`, `--type error` или `--type json`. В режиме `--tail` скрипт читает новые строки обычного файла, переоткрывает его после ротации и выводит итоговый отчёт по `Ctrl+C`. Архивы `.gz` поддерживаются для разового анализа.

Отчёт по access-логам показывает коды ответа, количество `4xx` и `5xx`, популярные IP и пути, частые `404`, User-Agent с признаками ботов и пути, совпавшие с подозрительными шаблонами. Параметры запроса исключаются из рейтингов URI и `404`. Каждая строка добавляет максимум одно срабатывание в `SUSPICIOUS`. Эти совпадения предназначены для ручной проверки. Отчёт по error-логам группирует строки по уровню и сообщению. Оба отчёта показывают количество пропущенных строк. Счётчики точные, поэтому расход памяти зависит от числа уникальных ключей в логе.

### Формат JSON Lines

Одна строка содержит один объект. Обязательны строковые `ip` и `uri`, а также `status` из трёх цифр в виде числа или строки. Поле `agent` может быть строкой, `null` или отсутствовать.

~~~json
{"ip":"192.0.2.10","uri":"/api/health?verbose=1","status":200,"agent":"curl/8.0"}
~~~

Пример настроек Nginx для секции `http`. Директиву `access_log` можно также задать для конкретного сервера.

~~~nginx
log_format tools_json escape=json
    '{"ip":"$remote_addr","uri":"$request_uri",'
    '"status":"$status","agent":"$http_user_agent"}';

access_log /var/log/nginx/access-json.log tools_json;
~~~
